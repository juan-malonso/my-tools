# AI Development Rules & Coding Standards

## 1. Linting & Core Conventions

- **Strict Adherence:** Always read and follow the project's linter configuration (`.eslintrc`, `prettierrc`, `tsconfig.json`).
- **Typing:** Use strict typing. Avoid `any`. Prefer `interface` over `type` for object definitions unless unions/intersections are required.
- **Modern Syntax:** Use ES6+ features (Optional chaining, Nullish coalescing, Destructuring).

## 2. Semantic Naming (Context-First)

- **Descriptive Variables:** Variable names must convey "what" and "why". Avoid generic names like `data`, `res`, `val`.
- **Booleans:** Must use prefixes: `is`, `has`, `should`, `can`, `did`.
- **Functions:** Use [Verb] + [Noun] (e.g., `fetchUserData`, `validateEmail`).
- **Consistency:** Maintain the existing naming casing (PascalCase for components/classes, camelCase for variables/functions).

## 3. Architecture & Modular Design

- **Single Responsibility Principle (SRP):** Each file and function must do only one thing.
- **Granularity:** Keep functions small (max 25 lines). If a function grows, extract logic into smaller, reusable helper functions.
- **Folder Structure:** Follow the established directory logic. Group by feature or domain if the project scales.
- **Early Returns:** Prefer guard clauses to avoid deep nesting:
  ```javascript
  if (!user) return null;
  // proceed with logic
  ```
